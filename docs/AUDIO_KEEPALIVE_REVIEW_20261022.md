# TunBox 可选音频保活与后台任务自检

状态：源码与自动回归完成，HarmonyOS SDK 26.0.0.105 调试 HAP 编译通过；长时间真机锁屏验收待完成。

基线：`xiaoli8571/TunBox`，`main` / `v0.4.3`，提交 `cfcc5c5aa93d45a627ce70abebbab0487b879410`。

## 使用方式

设置页新增「后台连接 → 音频保活（下次连接）」选项，默认关闭。打开后重新连接，才尝试音频保活；关闭同样在重新连接后生效。旧配置缺少此字段时仍关闭，只有布尔值 `true` 才启用。

音频模式持续播放本地生成的低音量 PCM 信号，创建 AVSession 媒体卡片。播放器音量参数为 0.03，不修改设备系统音量；不能保证任何耳机或音量设置下完全听不见，也不能保证没有额外耗电。没有麦克风采集、远程音频或音频文件下载。

默认关闭时保持原来的 taskKeeping → dataTransfer 路径。启用音频时仅申请 audioPlayback，不叠加 dataTransfer。音频创建或任务申请失败时清理音频资源并回到原方案，日志记录实际结果；开关表示用户偏好，不代表系统必定授予该任务。

## 30 秒自检

- 主页、前后台切换及快捷连接路径接入同一会话自检。
- 仅在连接意图与权威连接状态都有效时查询实际后台任务，不向外网发送保活请求。心跳无法确认状态时，权威判定可能使用本机 controller 认证探活，见 `FOREGROUND_SESSION_REVIEW_20261022.md`。
- 存在任务时不重复申请；系统暂停时不把任务当作丢失；查询报错时保留未知状态。
- 无取消回调但任务确已丢失时，先记录并等待至少 30 秒，复查后再补申请。因此不是承诺 30 秒修复。
- 用户停止、系统判定使用不当以及已有退避限制继续生效，不照搬取消后 1 秒无条件申请。
- 自动补申请共享最多 3 次预算，页面刷新不能绕过；成功或显式用户重新连接可重置预算。

这些定时器运行于应用进程内，不是系统唤醒任务；进程被冻结或杀掉时不保证执行，更不能保证自行重启进程。

## 生命周期

- 正常断开、失败释放时停止自检、音频、AVSession 和任务进度更新。
- 任务申请与释放串行化，并检查会话代次，防止断开后的迟到回调重新登记后台任务。
- 电话/其他音频打断，或用户在媒体卡片暂停/停止时，停止音频保活并抑制自动播放；需要用户显式重新连接才恢复。
- 系统恢复暂停任务时不会直接把已经停止的音频记作正在播放。
- audioPlayback 与 taskKeeping 均不使用 dataTransfer 的实况窗进度更新。

## 后续验收建议（未执行）

由工程维护者按项目现有签名、安装流程完成真机验收：

1. 音频选项关闭与开启分别测试：锁屏 30 分钟、2 小时，并记录系统版本、实际任务类型、取消/暂停原因、前后电量。
2. 解锁后先在浏览器访问代理网站，再打开 TunBox，避免把「回前台自愈」误判为锁屏期间始终在线。
3. 验证主动断开、媒体卡片暂停、电话/其他音频打断，以及音频不可用时的回退；确认没有残留播放或抢占音频焦点。
4. 验证后台任务查询失败、一般性系统取消及系统暂停时，没有重复任务、立即重挂或虚假成功状态。
