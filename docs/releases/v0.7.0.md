## 相比 0.6.8 包内的功能变化（工作区已含，随本包出厂）

- **按订阅记忆节点**：`AppSettings.preferredNodeNamesBySubscription`，切回某订阅时回到上次在该订阅选的节点（见 `docs/PROFILE_NODE_MEMORY_2026-10-27.md`）。
- **切订阅三处一致**：只点订阅名切 profile 时同步重锚出口，订阅页勾选 / 「当前连接节点」/ 主页不再互相矛盾（见 `docs/SUBSCRIPTION_SWITCH_NODE_SYNC_FIX_2026-10-28.md`）。
- **架构整改 Phase 1/2**：`ConnectionEvents`、`UnifiedScheduler`、`KernelSelectionManager`、`ReconnectPolicy`、`ProfileRepository` 落地，Settings 并发写收口（见 `docs/TUNBOX_ARCHITECTURE_REMEDIATION_PLAN_2026-10-28.md`、`docs/VPN_STATE_MACHINE.md`）。
- **设置页「DNS 接管」开关**（0.6.8 重打包已含）：默认开，YAML 为唯一真源，关掉后不写 `tun.dns-hijack`、不下发 DNS、不产生 fake-ip。

## 构建与验证

```powershell
$env:DEVECO_SDK_HOME = 'C:\Program Files\Huawei\DevEco Studio\sdk'
# 先 clean（资源编号门禁前置条件）
hvigorw clean --no-daemon
hvigorw --mode module -p module=entry@default -p product=default assembleHap --no-daemon
hvigorw --mode project -p product=default -p buildMode=release assembleApp --no-daemon
# 签名口令由本地环境变量注入（口令不入库、不写进任何文件）
powershell -ExecutionPolicy Bypass -File C:\Worker\TunBox\sign-nexus-package.ps1 -Kind app
```

结果：

- `clean` / `assembleHap` / `assembleApp` 均 `BUILD SUCCESSFUL`（`WARN: No signingConfig` 属预期）。
- `pack.info`（HAP 与 .app 内）均为 `0.7.0 / 540`。
- `sign-nexus-package.ps1 -Kind app` 双层签名通过；`hap-sign-tool verify-app` 对签名 HAP 与签名 .app 均输出 `Digest verify result: true` + `verify-app success`。
- 门禁：`verify-build-profile` 13/13 PASS；`verify-ui-resource-bindings` 四图标编号 debug + release 两套 PASS；
  `verify-vpn-architecture` 313/313；`verify-config-generation-integrity` 131/131（0 deferred）；
  `verify-shipped-dns-fix` 对 0.7.0 签名包 7/7（DoT 端点仍在、无 DoH-443 / respect-rules）。
- 包内字节：`ets/modules.abc` 含 `dnsOverrideEnabled` / `readDnsEnable` 与 `0.7.0` 字样。
