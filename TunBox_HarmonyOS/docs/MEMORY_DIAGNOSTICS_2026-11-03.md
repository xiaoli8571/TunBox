# 0.8.1（554）内存异常止损与诊断

## 已验证的问题与本轮修复

- `/memory` 是持续输出 NDJSON 的流式接口，而旧页面把它当作会结束的普通 HTTP JSON 请求。页面移除此请求，统一显示 VPN 扩展进程的 PSS+SwapPss（KiB 转字节），样本带时间戳，超过 15 秒不显示。RSS 和 Go heap 仅作独立诊断指标，不混用。
- `hidebug.getPss()` 从扩展的 ArkTS 线程移至 taskpool，单航班采样，停止/新生命周期后的迟到结果丢弃，避免阻塞心跳。
- socket 保护原来忽略负回执，并在失败、超时、通道失效时继续拨号。真实 VPN 现仅允许正回执；800ms 超时、取消、负回执、无保护会话、管道写失败均阻止拨号。无 TUN 的独立测速仍可运行。系统 Go resolver 的 Dial 同样挂保护钩子。
- HarmonyOS 构建保留 mihomo loopback detector，不再被 CMFA 标签顺带关闭。
- 原生启动入口此前未调用初始化导出，现启动时在生命周期锁内设置 home/config，C-shared 入口先建立 stdout/stderr 有界日志采集。
- 系统 MEMORY_LEVEL_CRITICAL 时留存原因、停止 VPN、关闭跟踪连接并清除自动连接意图；不使用固定内存阈值误杀大型规则配置。

这些是代码中可确认的缺陷及风险路径，**尚未在反馈者设备复现其 80MB→1GB→卡死的完整过程**，不能断言已证明唯一泄漏根因。

## 一键导出

入口：设置 → 关于与隐私 → 一键收集并导出日志。通过系统文件选择器保存 UTF-8 `.txt`，取消选择不会收集；单航班执行；文件采集在 taskpool 完成，不上传任何服务器。

报告覆盖：

- AppLogger 跨启动留存日志：应用、VPN、快捷入口、后台订阅任务（同进程共享当前 logger）；每个角色 1MiB × 3，缓冲最多约 16Ki 字符。
- Go stdout/stderr（拨号、DNS、TUN、启动错误等）：2MiB × 4，磁盘失败不会关闭采集管道；退出前最近未处理的管道数据仍可能丢失。
- 系统投递的本应用 crash/freeze 事件元数据（记录于应用日志，单行有界；不宣称包含完整系统 dump）。
- 启动阶段和运行阶段每 5 秒的 Go 堆、GC、RSS、goroutine、FD、活动连接、保护成功/失败计数，历史 1MiB × 3。
- 新鲜 PSS、运行状态、心跳、启动错误和最近一次系统严重内存压力原因。
- 设备型号、OS、SDK、版本、收集时间、当前连接状态。

严格白名单读取，不导出 YAML、订阅数据库、preferences、密钥或节点配置；二次脱敏 URL、常见凭据字段、UUID、IPv4 和 PEM 私钥。任意日志文本无法保证完全匿名，分享前仍应检查。单个来源最多读取末尾 2MiB，切断的首条记录丢弃；缺失、不可读和截断都会标记。目标文件写失败不能报成功。

普通应用不能读取全系统 hilog 或其他应用日志，未额外索要系统权限。轮转日志会覆盖更早记录，因此复现后尽快导出。

## 验证边界

回归脚本执行生产 ArkTS 逻辑、替换 OS 边界；Go 保护策略/轮转器有可在本机运行的独立测试。另做真实 OpenHarmony arm64 内核交叉编译、DevEco release 清理构建及资源编号校验。未将离线回归称为真机验证，未向设备安装本轮产物。
