# 本地 YAML 选台湾手动后启动变直连

日期：2026-11-03。目标：0.8.1 / 558 装机测试包；用户自行覆盖安装复测。

## 现场与根因

本轮仅从已连接设备只读抓取 hilog，没有重装、改订阅或切换运行状态。17:19:08 的旧包日志记录 `node="直连" group="AI" effective="直连"`；17:19:09 保存的组选择恢复日志为 `rule=(no match)`；17:19:10 连接目标是 `AI → 直连`。因此错误发生在启动选点链，不只是主页显示。

1. 保存的组名或 provider 节点不在静态节点表时，偏好恢复返回空，调用方回落到静态“直连”。用户文件的静态代理只有 Direct，远程代理由 HTTP provider 加载。
2. 构建器按第一条指向 Selector 的规则识别主组，因而把 AI 认作主出口；用户面板选择保存在“默认代理”。
3. 文本目标解析只认叶子；运行时 provider 名称和子策略组可能被替换成静态叶子。全局叶子钉选还会改变其他业务组。

未在报告中保存私有 provider 地址、凭据、完整配置或完整设备日志。

## 修复行为

- 当前 profile 的保存偏好可恢复为待内核验证的影子目标，覆盖无目录快照、应用进程重启、组名和 provider 节点。其他订阅的快照不能提供当前目标。
- 默认候选忽略静态 Direct/Reject 等策略。完整 profile 没有已保存选择时，保留并回读配置默认出口，不钉到唯一的静态 Direct。
- 主组使用声明顺序中的第一个非 GLOBAL Selector；AI/YouTube 规则的优先级不决定主出口。全局模式明确使用 GLOBAL。
- 构建器保留合法子组和必须等待运行目录才能验证的 provider 意图，不能提前改写手动偏好。
- 启动先恢复当前订阅的组选择，再在主组内应用本次显式意图。具体节点沿可控制的 Selector 链从内向外设置；选择自动组则保留该组自身策略。独立 AI、YouTube 等组不被全局改写。
- PUT 后检查每级 `now` 并确认实际叶子。目标尚未加载时有界等待；目标缺失、Compatible 空占位或读回失败均不能改成 Direct 并报告成功。用户停止及端点变更会作废迟到写入。
- 在线手选同样沿当前主组切换。自动组的实时出口变化只更新实际出口展示，保留手动组意图，防止下次启动被固定成某一叶子。

## 验证与边界

`verify-startup-selection-runtime.mjs` 执行生产偏好恢复、配置目标解析、controller API 和启动钉选阶段。真实 mihomo 核心从 loopback HTTP provider 加载测试节点。用户原 YAML 只参与 native normalization 和目标解析，不拉取其私有 provider。

17 项运行回归通过，覆盖组/具体节点冷恢复、跨订阅隔离、默认候选、策略偏好保留、AI 规则优先级、原文件台湾组、子组启动、具体节点优先于旧 Direct、完整内核重启、默认策略回读、GLOBAL、缺失目标拒绝、自动组策略、空 provider 拒绝、取消和端点作废。另有 20 项测速/生命周期回归通过。

以上不能替代 HarmonyOS VPN 启动和用户机场出口 IP 的装机验收。设备日志证明旧包故障；没有声称新包已在手机验证。

## 装机复测

1. 覆盖安装 558，保留订阅。断开时重新选“默认代理 → 台湾手动”，启动，确认保持该组并获取台湾节点出口 IP。
2. 停止，进入“台湾手动”选具体节点，再启动，确认实际出口仍是所选节点。
