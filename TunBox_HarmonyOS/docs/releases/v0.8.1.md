## 本版改动

### 1. 网络切换与恢复链路

- Wi-Fi、蜂窝、以太网和未知承载统一使用保守 TUN MTU `1360`，网络切换不再因为承载类型变化重建 TUN，也不会消耗故障恢复预算。
- `NetworkStateWatcher` 快照新增 netId、接口名、地址、DNS、validated、metered；断网立即发布，其余变化用 200ms 尾部合并，避免恢复事件被去抖窗口永久吞掉。
- Extension 成为活动隧道的单一网络执行者；App 侧只观察网络变化，不再并行拆除并重建会话。
- 新增轻量网络更新链路 `TunBoxUpdateNetwork` → NAPI `updateNetwork` → `CoreBridge.updateNetwork`：DNS-only 变化刷新解析器但保留现有连接；网络身份变化才清理旧跟踪连接，不重建 TUN、不重启健康 Core。
- 忙碌恢复期间保留最新网络快照；迟到的旧更新失败不会覆盖新状态。连续稳定运行 60 秒后重置故障恢复预算。

### 2. DNS、IPv6 与运行配置契约

- 所有订阅/用户配置合并完成后统一校验 TUN MTU 与 DNS/IPv6 契约，避免订阅 DNS 覆盖导致应用假 IPv6 池丢失。
- fake-ip 模式在允许 IPv6 时固定补齐 `fdfe:dcba:9876::/64`；真实地址 DNS 模式保留订阅上游和模式，但不宣称平台无法可靠接管的 AAAA 流量。
- IPv6 健康探针文案区分“DNS 返回 AAAA”和“真实 IPv6 出口已验证”，避免把解析结果误报为端到端连通。

### 3. Native 内核与生命周期

- bridge 不再静默把 YAML 选定的 TUN 栈覆盖为 gVisor，启动诊断记录实际 stack、MTU 与 congestion 配置。
- Protect Stop 先取消等待者，再由统一释放路径关闭会话写端，修复重复启动/停止时管道读端可能永久阻塞的问题。
- 重新构建 arm64 `libgojni.so`，同步更新导出头文件与 SHA-256；Windows 构建脚本规避 `HTTPS_PROXY` / `https_proxy` 重复环境键导致的 Go 构建失败。

### 4. provider-only 节点可见与选择

- 节点页和主页订阅面板可合入带 profile 归属戳的 CoreCatalog 运行期节点，解决 `proxy-providers/use` 只有内核节点、App 本地节点表为空时列表不可见的问题。
- 未连接时预热/复用 mihomo 并刷新 `/proxies`；provider 影子节点可选中，但不会被当成本地静态节点删除。
- 继续严格校验 CoreCatalog 与当前 profile 的逐字归属，避免旧订阅节点串入当前订阅。

### 5. 验证与发布素材

- 新增网络运行时与 provider 节点可见性回归脚本，并同步调整纯逻辑、VPN 架构、配置单一真源和启动资源校验。
- 发布素材新增 phone/tablet 截图，清理旧 AGC 图标副本。
