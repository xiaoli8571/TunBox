# 0.6.0 启动依赖复查（528）

## 为什么只影响部分用户

已经复现的故障需要组合条件：配置实际使用 GEOIP/GEOSITE 或远程规则；所需本地数据缺失、损坏或未成功铺盘；内核启动期间补下载又失败/超时。不同订阅、已缓存的数据、写盘状态和网络可达性会让结果不同。没有触发这些规则、或已有有效数据的用户可能正常。

前一轮已用同源 Mihomo 复现：缺少 MMDB 且自定义 GEOIP 被发射时启动失败，关闭规则引擎时通过；527 已将该路径接入资产就绪闸门并将规则引擎默认值改为 false。没有每位受影响用户的日志，不能把所有个案认定为这一条原因。

## 本轮补修

GeoDataInstaller 原实现存在：

1. 复制前就设置进程级 installed，读取资源/写盘失败后同进程不再重试。
2. 只按大小保留文件，同样大小或更大的错误内容会一直留下。
3. 缓存在本进程内被清除后，仍因 installed 标志不重建。
4. 直接 TRUNC 目标且不检查写入长度，可能留下残缺目标；共享 ArrayBuffer 的视图也会写出不属于资源的字节。

现在按路径、大小、mtime、inode 缓存结构检查结果：MMDB 检查尾部元数据标记，GeoSite framing 按同源内核 verifyGeodata 的顶层格式检查。缺失或明显损坏时纯本地修复；失败不记成功；写入独立临时文件、检查字节数/结构，关闭后原子替换。有效已更新文件保留，不按随包大小强制降级。

结构检查并不等于数据库所有记录的全量语义验证；最终接受性由真实内核的解析/启动判断。磁盘无空间、权限错误、用户自定义无效配置或外部订阅资源永久不可达仍可能产生明确错误，不能承诺所有环境永不失败。
