# GitHub 推送边界（永久规则）

用户于 2026-11-13 明确要求：禁止推送任何敏感数据、任何脚本、任何签名文件。此规则适用于未来所有会话、提交、分支、标签和附件。

## 禁止上传

- 密码、令牌、Cookie、私钥、订阅凭据、账户配置、个人或设备数据、未脱敏日志和取证资料。
- 所有 scripts 目录内容，以及构建、测试、安装、设备推送、签名、发布等脚本；包括 sh/bash/ps1/bat/cmd/mjs/cjs/py 等脚本文件。
- 签名配置、证书、密钥、p12/keystore/jks/cer/p7b/pem/key 文件和签名日志。
- 默认禁止 HAP、APP、签名包、归档包、生成产物、构建缓存、临时文件、本机技能和凭据文件。唯一例外：用户明确要求发布时，可经本地上传闸门上传一个已验证为未签名且版本匹配的 `TunBox-<版本>-unsigned.hap` 到对应 GitHub Release；不得上传其他包。
- 未经审核的二进制、Windows 子仓库及无关项目改动。

## 允许范围

仅允许经过逐项审核的应用源码、必要的非敏感配置、资源源文件、第三方声明和规则文档。扩展名为文本不等于安全，源码中也不得携带真实凭据。

## 每次推送必须执行

1. 确认目标为 xiaoli8571/TunBox，使用 neworigin；不得推送旧的冻结仓库。
2. 获取远端基线，审核整个待发布提交范围。已有本地提交包含禁止内容时，不得直接推送，也不得仅在末尾删除后连同历史推送；应从远端基线形成不带这些本地父提交的干净白名单提交。
3. 只暂存逐项审核的明确路径，禁止 git add -A 或 git add .。
4. 检查文件清单及完整补丁，扫描敏感值、脚本、签名材料、日志和生成文件。只输出命中文件与位置，不输出秘密值。
5. 提交后再次核对父提交、待推送提交和文件清单；未通过不得推送。
6. 本地原工作区及未获授权的历史不重置、不覆盖；推送使用独立发布分支或独立索引。
7. 不自动发布 Release 或上传附件。用户直接要求发布特定版本的未签名 HAP 时，才可创建/更新对应 Release 并上传唯一未签名 HAP；必须使用本地上传闸门并核实最终资产清单。任何其他例外须另行明确授权。

本规则优先于旧技能或文档中允许上传脚本、测试脚本或安装包的条款。不能确认是否敏感的内容不上传。
