# 0.6.0 保活复查（2026-10-23）

## PR 和版本差异

本地合并提交 `d50845f` 对应 PR #5（arsenalpoll）。相比 0.5.0 的 `9b8c826`，它增加了：

- 可选的 AudioRenderer + AVSession 音频保活，默认关闭，保存后下一次连接生效。
- 每 30 秒查询真实后台任务；任务确实丢失时有限次补挂。
- 注册/释放串行化、会话代次检查，防止断开后的迟到结果重新注册后台任务。
- 打开前台只接管确认存活的会话，避免仅凭陈旧心跳就拆建隧道。

上述 PR 功能仍在 0.6.0。当前工作区此前对相关类的改动主要是品牌名称替换，并未移除音频守护和自检。但 0.5 使用 `ssrvpn_settings`、0.6 使用 `tunbox_settings`，没有自动迁移时，旧版开启的音频保活会回到关闭默认值。按用户决定保留现状，由用户备份/恢复或重新配置。

## 已修复（构建号 527）

1. **自检发现后台任务从暂停恢复时漏接 dataTransfer 进度心跳。** 原实现只恢复 `registered=true`，已 detach 的五分钟进度任务没有重新 attach。现在自检恢复时接回心跳，健康自检不重置已有定时器；同时允许查询已暂停的任务，补足系统恢复事件丢失的情况。
2. **旧会话取消/暂停事件可以清掉新会话的守护。** 新增独立的 continuousTaskId 记账（不是 notificationId），事件分发前校验归属，并保留有限的旧任务 ID，过滤重连中迟到的旧事件；当前任务的用户停止仍照常生效。
3. **系统普通取消后多等一次缺失确认窗口。** 系统取消事件本身已经证实任务丢失；现在与自检共用同一个 30 秒退避，避免再叠加第二个等待窗口。真正未知的查询结果仍保守处理，自动重试仍有限次。

音频被媒体控制/焦点中断时仍停止播放，恢复音频需要显式连接操作；没有自动重播或把音频保活改成默认开启。普通模式仍按设备实际授权协商 taskKeeping/dataTransfer。

## 本轮验证边界

- 保活生产源码行为用例 26 项，含暂停恢复、丢失恢复事件、迟到取消/暂停、重连中迟到事件、当前任务用户停止、退避及重试预算。
- 前台会话恢复用例 24 项。
- 卡片守护检查覆盖真实策略与共享注册入口；旧断言仍要求 QuickToggleAbility 直接注册 dataTransfer，已按现有共享入口更新。
- 设备当前未连接，未测锁屏长时存活率、耗电和不同系统省电策略，不能据本地回归宣称实际保活超过 0.5。

同包还包含规则引擎默认关闭、自定义 GEOIP 缺库保护和移除测速组级失败/超时统计提示。版本名称仍为 0.6.0。
